| AGD-005 | A publication carries the whole Agency as JSON and production runs off tags, not rows: `Status` becomes a unique `Channel` (several tags live at once, one per channel), rollback is re-channelling an archived tag, a Draft may fork from a tag, and `WorkPlan`/`ContextSource` are decommissioned | 2026-09-17 | Full decision record: [todo_details/AGD-005.md](todo_details/AGD-005.md). Prompted by the user challenging a cosmetic `scope` field in the Studio's Issues panel and arriving at a better model than any option offered: "live" is a state on the tag, not a tier of rows. Implemented for `mwanachama-backend-agency` as **AG28** (document + channel model), **AG29** (fork-from-tag) and **AG30** (WorkPlan/ContextSource removal) — see [../3. implementation/todo_done.md](../3.%20implementation/todo_done.md). Two things this doc did not anticipate: the existing import/export shape (wakala-api decision #19) served as the document format unchanged, so no new format was invented; and `AgencySnapshot` turned out to be an empty stub too, meaning the repo had two receipt-shaped records and zero snapshots. **The consumer cutover to reading the tag is deliberately not filed as a row** — it needs its own pass per consumer, and almost nothing reads agency structure in production today (the gateway's boot-time module gating and K6's RACI lookup are the whole list). Four questions left open in the record: validation timing (working set vs. document), whether staging is gated as strictly as production, any bound on document size, and what pre-AGD-005 publications become (assumed archived history, not back-fillable). |
| AGD-006 | There is no live: every draft-scoped table's `DraftID` becomes non-nullable, `forked_from_type` drops `"live"` (empty now means "start a fresh empty Draft"), the live-immutability rule and `PromoteDraft` are deleted outright (`Draft.Status` collapses to `open`/`archived`), and `PublishAgency` publishes directly from a named Draft's own rows, no merge step | 2026-09-19 | Full decision record: [todo_details/AGD-006.md](todo_details/AGD-006.md). Implemented for `mwanachama-backend-agency` as **AG33–35** (landed as one pass — schema and behavior are too coupled to ship independently) — see [../3. implementation/todo_done.md](../3.%20implementation/todo_done.md) for the full record, including two things this doc's own text undercounted (twelve draft-scoped tables, not nine — `Module`/`ObjectiveModule`/`Issue` share the shape without a Code) and two bugs the implementation found along the way, not anticipated here: `LookupFlowStep`/`ListEventFlowSteps` had their own hardcoded live-scope query outside `scopeQuery` entirely, and the top-level `GET /issues` route had to be deleted outright rather than adapted, since there was no longer any scope for it to mean. `AgencySnapshot` (already flagged as an empty stub by AGD-005) is now fully dead code with `PromoteDraft` gone — filed as **AG36**, a decision this doc doesn't make. Cross-repo consumer cutover (`mwanachama-wakala-api`, `mwanachama-wakala-studio` — including the original "Edit button on the drafts page" ask that started this whole design conversation, `mwanachama-backend-api-kazi`/`-api-shared`, `mwanachama-backend-api-gateway`) is **not** closed by this — filed on [../3. implementation/todo.md](../3.%20implementation/todo.md), not this repo's own work to finish. |
