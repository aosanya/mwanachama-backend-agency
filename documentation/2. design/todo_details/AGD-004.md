# AGD-004 — Publish-time validation, blocking error severity, operator tag

Design session of 2026-09-16, run via the (adapted) `dev-research.md`
protocol. Started from: "I want that the agencies are validated when the
publish button is posted. It should tag the agency" — today
`PublishAgency` (`publication_impl.go`) checks exactly two things (the
named Draft is `promoted`; the content hash differs from every existing
publication) and validates **no content at all**, while the only
validation machinery in the repo — AG20's Issue scan
(`issue_impl.go`'s `scanDraftIssues`) — is Draft-only
(`ErrDraftIDRequired` on `""`) and produces only `warning`/`info`.
`models.IssueSeverityError` is declared but produced by nothing.

## Decisions

1. **Publish is gated by the Issue scan: `error` blocks, `warning`/`info`
   pass.** `PublishAgency` runs the scan against the live scope inside its
   own transaction, before hashing; any `error`-severity finding refuses
   the publish with a new sentinel (`ErrPublishValidationFailed`, mapped
   to 409 in `routes/publication.go` and to an `IsError` result naming
   the findings in `mcp/agency.go`). Warnings and info never block.
   Considered and rejected: any-issue-blocks (today's info-level "Goal has
   no Objectives yet" would stop an early agency from ever publishing —
   moot now that #3 promotes it, but the rule stays severity-keyed, not
   any-issue); advisory-only scan-and-record; and a confirm/override flag
   (nothing may publish past an `error`, operator or MCP agent alike).

2. **The scan becomes scope-agnostic; `ErrDraftIDRequired` is deleted.**
   `ListIssues(ctx, "", filter)` scans the live Agency the same way it
   scans a Draft — `scanDraftIssues` already routes every query through
   `scopeQuery`, which treats `""` as live; the guard is the only thing
   stopping it. `IssueRow.DraftID` becomes nullable-`""`-means-live like
   every other Draft-scoped row, and live findings are regenerated
   delete-and-reinsert on each call exactly as Draft findings are. This
   is what lets publish (a live-scope operation) and the scan (previously
   Draft-only) meet at all; it also gives `mwanachama-wakala-studio`'s
   Issues panel a live view for free (its `noDraft` special case —
   `useAgencyDashboard.ts` ~756 — goes away). The
   routes surface needs a live-scope path: today's only route is
   `GET /drafts/{draftID}/issues`, which cannot express `""`.

Superseded in part by [AGD-009](AGD-009.md): a Workflow with no Objective is an
`error` in place of a WorkItem with none; the dangling checks name
`workflow_objective` and step-scoped `role_assignment`; "Objective with no
Accountable" and "two Accountables" no longer exist.

3. **Four check families become `error` severity — the first producers
   of `IssueSeverityError`:**
   - **Dangling references** (all net-new checks): a `WorkItem` whose
     required `ObjectiveID` resolves to no same-scope Objective; a
     `RoleAssignment` whose `RoleID` or `ObjectiveID` resolves to no
     same-scope row; a `ValueAttachment`/`RuleAttachment` whose
     `TargetCode` no longer resolves against the live scope (AG22 stores
     Codes precisely so reads re-resolve — a dead Code is a real orphan);
     an `EventFlowStep` whose `workflow_code` matches no same-scope
     Workflow (the join is by business key; nothing enforces it today).
     All are reachable through ordinary deletes — see AG27.
   - **Objective with no Accountable** — promoted from `warning`.
   - **Empty structure** — an Agency with zero Goals (net new), and a
     Goal with zero Objectives (promoted from `info`).
   - **Workflow with zero WorkItems** (net new).
   The scan reports these as `error` in every scope all the time (the
   Issues panel shows them while drafting); they only *block* at publish.

4. **Tag is operator-supplied with auto fallback.**
   `PublishAgency(ctx, draftID, tag string)` — a non-empty tag names the
   release ("2026-Q4 restructure"); `""` falls back to today's
   `v{version}`. Tags must be unique across publications: new
   `ErrDuplicateTag` (409). `Version` stays the machine-assigned
   monotonic number and remains the key `GetPublication`/
   `UpdatePublicationStatus` take. Rejected: tag-required (breaks the
   existing no-tag call shapes, including direct-live publish); a
   separate `Label` field beside a machine `Tag` (two near-synonymous
   columns); stamping the Agency row itself (the active publication is
   already readable via `ListPublications(status=active)`).

5. **The Studio surfaces publish validation through the existing Issues
   panel, wiring the Publish button for the first time.**
   `CanvasTopbar`'s Publish button (`topbar.tsx` — a hardcoded
   `disabled` placeholder today) becomes real: it takes the optional tag,
   calls publish, and on `ErrPublishValidationFailed` opens the existing
   Issues panel (`AgencyDashboardDetail.tsx`) filtered to `error` — one
   issue surface, not a second pre-flight dialog. On success it shows the
   new publication's Tag/Version. Rejected: a dedicated pre-flight modal
   (second render path for the same findings); backend-only this pass.

## Found along the way (filed as AG27, not fixed here)

Three delete paths *produce* the dangling references decision #3 now
detects, through the ordinary UI:

- `DeleteGoal` (`goal_impl.go:98`) and `DeleteObjective`
  (`objective_impl.go:97`) cascade into `RoleAssignment` but never touch
  `WorkItem` — yet `WorkItem.ObjectiveID` is *required* (AG12; there is
  no untagged WorkItem). Deleting an Objective orphans every WorkItem
  under it. (`DeleteWorkflow` — AG20 — does cascade its WorkItems; the
  Goal/Objective paths predate required-`ObjectiveID` semantics.)
- `DeleteRole` (`role_impl.go:94`) deletes only the Role row; its
  `RoleAssignment` rows survive pointing at a dead `role_id`, even though
  `DeleteObjective` cleans the same join table from the other side.

Validation makes these visible; AG27 stops them being created. Both are
worth doing — the scan still has to catch rows that predate the fix.
