# AGD-010 — Risks live in the agency draft

Owner decision of 2026-10-31: risks, with their threats and consequences, are
part of the agency, like goals and roles. They are edited in a draft, ship in a
publication, come back on a fork from a tag, and travel with import and export.
Until now they lived only in `mwanachama-backend-riskmanager`, a separate
register per instance with no draft and no publication.

## What the agency stores

| Object | Code | Fields |
|---|---|---|
| `risk` | `RK-n` | `title` and `top_event` required; `hazard`, `owner` optional. `owner` is a role code or name, kept as written. |
| `risk_pathway` | `RP-n` | `risk_id` and `title` required; `side` is `threat` or `consequence`; `scenario` optional. |

Both are draft-scoped (`draft_id` required, never blank), carry the common
`created_at`, `last_updated`, `deleted` columns, and mint their code once, in
the creating transaction, from the shared code sequence.

## The operations

| Tool | Route | Notes |
|---|---|---|
| `agency_create_risk`, `agency_get_risk`, `agency_update_risk`, `agency_delete_risk`, `agency_list_risks` | `/risks`, `/risks/{risk_id}` | List narrows by `code` and `title`. Update keeps code, draft and creation time. Delete removes the risk's pathways in the same transaction. |
| `agency_create_risk_pathway`, `agency_get_risk_pathway`, `agency_update_risk_pathway`, `agency_delete_risk_pathway`, `agency_list_risk_pathways` | `/risk-pathways`, `/risk-pathways/{risk_pathway_id}` | List narrows by `risk_id`, `side` (exact) and `title`. Create refuses a risk that is not in the same draft (404). Update keeps the risk, code and draft. |

Errors: `ErrRiskNotFound` and `ErrRiskPathwayNotFound` answer 404,
`ErrInvalidRisk` and `ErrInvalidRiskPathway` answer 400. The actions are
`agency.risk.*` and `agency.risk_pathway.*`; `risk_id` and `risk_pathway_id` are
marked as references like the other ids an operator works with.

## Drafts, publications, import

- A fork of a draft copies both objects with fresh ids, the pathways remapped
  onto the copied risks, codes kept.
- A publication's document gains `risks` and `risk_pathways`, in the import and
  export shape; `applyDocumentToDraft` restores them, and the code sequence is
  raised past the restored codes so the next risk is `RK-n+1`.
- The content hash covers both, so adding or editing a risk is a change that
  needs a new tag.

## The issue scan

A pathway whose risk is gone is an `error`. A risk with no threat or no
consequence raises nothing: it is a draft in progress, and the gaps belong to the
risk manager's own gap list, not to publishing.

## What this does not do

- Controls, barriers, evidence, ratings and actions stay in the risk manager;
  the agency holds only the bow-tie's two arms.
- Nothing reads these objects outside this repo yet. The wakala-api tools come
  with the library, but its mount of the separate risk register, the review's
  Risks reader and the console's Risks page and chat still point at the risk
  manager (row AG101).
