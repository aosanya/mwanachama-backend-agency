# AGD-008 — A module is switched on by a switch or a step, not by an objective link

Owner decision of 2026-10-30. Supersedes decisions 4-6 of [AGD-002](AGD-002.md).

## Why the link went

`ObjectiveModule` made an objective "need" a module, with a mandatory
rationale, and that link was the only thing that could switch a module on. A
designer who wanted `forms` had to invent an objective to hang it on and write
a reason nobody read, while the workflow steps that actually use forms
(`fill_form`, `send_form`, `yes_no`) said nothing. The link, its four tools,
its table, its rationale and the `objective_modules` section of the published
document are removed.

## The rule

A module reads as enabled (`enabled`) when, in its own draft:

1. it is `locked`, or
2. its stored flag is on (`explicit`), or
3. a work item of the draft has a kind the catalog lists for it
   (`needed_by_steps`),

and then every module those require (`requires`, transitive) is enabled too.

`models/modules_catalog.json` carries the step kinds per module in an optional
`step_kinds` array: `forms` takes `fill_form`, `send_form`, `yes_no`; `comm`
takes `notify`. The catalog refuses at package init a kind the step vocabulary
does not hold.

The stored flag is the module row's `enabled` column, now set explicitly by
`agency_set_module_enabled`. Switching a locked module off is refused with
`ErrModuleLocked` (409). Switching a module off while a step or a switched-on
module still needs it is allowed: the stored flag drops and `enabled` stays
true, `needed_by_steps` or the requiring module showing why.

## On by default

`auth` and `actor` are locked and on. `comm` is on by default but not locked:
the catalog row is `"enabled": true`, so `Provision`, a draft started from
nothing and the backfill seed it as switched on (`explicit: true`). Someone may
switch it off; a `notify` step then keeps it running and shows
`needed_by_steps: true`. A fork copies the stored flag with the rest of the row.

## What a consumer must change

- Read `enabled` as the answer; it is already the effective value. A
  publication's `DocumentModule.Enabled` is the effective value at publish
  time, so a consumer reading a publication needs no step logic.
- `agency_list_modules` and `agency_get_module` also return `explicit` (the
  switch) and `needed_by_steps`. Show the switch from `explicit`.
- Switch a module with `agency_set_module_enabled` (`draft_id`, `module_id`,
  `enabled`; `PUT /modules/{module_id}/enabled`). Do not look for
  `agency_attach_module`, `agency_detach_module`,
  `agency_update_module_rationale`, `agency_list_objective_modules` or
  `agency_list_module_objectives`; they are gone.
- Stop writing `objective_modules` into documents. An incoming
  `objective_modules` key is ignored, not an error, so old templates import;
  a module's `enabled` in an incoming document sets the stored flag. Import
  still adds the modules the switched-on ones require.
- Content hash: the `ObjectiveModule` records left the hash, so the first
  republish of an existing agency is a new version.
